# SnapRef-webui

[English](README.md) · [简体中文](README.zh-CN.md)

Forge Neo の **img2img** に **キャラクター参照生成（SnapRef）** を追加します。
主画像はキャラクター参照に使用し、出力は新しいノイズから生成します。
SnapRef v2a-pre2 の非対称注意、参照／対象別 LoRA、モード埋め込み、各ブロックの
K/V キャッシュを実際に実行します。

ローカルで検証したリリース候補です。あらゆる画像・モデルでの完全な外見維持を
保証するものではありません。[検証範囲](docs/testing.md)も確認してください。

## インストール

[Forge Neo](https://github.com/Haoming02/sd-webui-forge-classic/tree/neo)、Anima、
対応する Qwen テキストエンコーダーと Qwen Image VAE が必要です。検証環境は
Python 3.13.11、PyTorch 2.9.1+cu130、Gradio **4.40.0**、SageAttention 2.2、
RTX 5080 Laptop 16GB です。WebUI の Python 環境を使用してください。

この独立リポジトリを `extensions/SnapRef-webui` に配置して再起動します。
公開後は拡張機能の URL インストールも利用できます。`install.py` は不足依存のみ
追加し、Torch/Gradio の交換やホストソースの変更、起動時の重み取得は行いません。

## 基本操作

1. Anima base v1.0 と対応する VAE・テキストエンコーダーを選択します。
2. **img2img の主キャンバス**にキャラクター画像をアップロードします。
3. img2img / Sketch / Inpaint / Batch と同じ階層の **参照生成** サブタブを選択します。
   対応モデルでは、このサブタブに入ると SnapRef が有効になります。
4. **現在の img2img 画像を参照に使用**で主画像を再利用するか、新しいサブタブに直接
   アップロードします。直接アップロードするとこの選択を解除し、元のキャンバスは変更しません。
5. 新しい場面・動作・ポーズを入力し、**Resize to** で出力サイズを指定します。
   Euler / Simple、Shift 3、CFG 4.5、28 ステップから始めることを推奨します。
6. 生成します。**このモードではノイズ除去強度は使用しません。** 主画像を通常の
   img2img 初期潜在として扱いません。SnapRef の LoRA タグは不要で、追加しないでください。

例：`1girl, solo, sitting on a bench, crossed legs, night, street`。
キャラクターと画風モードは両方を参照し、キャラクターのみモードはモデルとプロンプトに
画風を任せやすくします。細部や衣装は変わる場合があります。

元のサブタブに戻ると SnapRef が無効になり、通常の img2img・インペイントの操作を復元します。有効時の
マスク、インペイント、高解像度補助処理、リファイナー、および「通常 img2img＋別の
キャラクター参照」の併用モードは未対応です。

## パラメーターと複数画像

| 設定 | 意味・既定値 |
|---|---|
| 参照強度 | 1 は学習時の注意重み、0 は無効、2 は 2 倍。LoRA 行列は拡大縮小しません |
| 忠実度 | 既定 1。低くすると負の分岐にも `1 − 忠実度` の重みで参照を加えます |
| 参照解像度 | 既定 1 MP。縦横比維持、縮小のみ、辺を 16 ピクセルに整列 |
| 個別に処理 | 同じキャラクターの視点・細部に適します。各ブロックで K/V を連結 |
| 横に結合 | 先頭画像の高さで左から結合し、全体に面積制限。異なる人物の特徴が混ざる場合があります |
| 画像重み | 0–2。主画像（使用時）、ギャラリー順。省略は 1、0 はエンコード省略 |
| 追加対数バイアス | 既定 0。`log（参照強度 × 画像重み）` に加算 |
| 負の分岐でも参照 | 既定オフ。オンでは負の分岐にも完全な参照を使用し、忠実度を無視 |
| 独立参照ガイダンス | 既定オフ。オン時の強度は 4.5、両分岐で参照を使用 |
| 補正・終了位置 | APG・1.0。この割合までステップごとに参照なし予測を 1 回追加 |
| キャプション | 既定は空。任意の外見タグで、出力の場面プロンプトではありません |

合計 **8 枚**まで。追加画像欄でドロップ・貼り付け・アップロード後に追加ボタンを
押します。サムネイルを選択して置換、削除、左右への移動ができます。重みは位置に
対応するため、並べ替え後はカンマ区切りの重みも更新してください。結合時の非ゼロ
個別重みは無視しますが、重み 0 は除外します。

強度・忠実度は上流の数式を保持します。明示的な負の分岐参照か独立参照ガイダンスを
有効にした場合、忠実度は無視されます。日本語・中国語・英語はモデルを再読込せず
切り替えられ、選択を保存します。初期値は Forge の言語、システム言語の順に確認し、
その他は英語にフォールバックします。

## 重みの検索と自動取得

Forge の `--lora-dir`、`models_path/Lora`（`--model-ref`、`--data-dir` 対応）、
既に登録された対応モデルの場所を再帰検索します。

* `snapref_v2a_pre2.safetensors`：既定で優先する BF16。
* `snapref_v2a_pre2_fp8.safetensors`：任意で優先する FP8 保存形式。

メタデータ、両分岐、宣言された対象行列を検証します。FP8 E4M3FN は作者の行別 FP32
スケールで復元し、モデルの計算型で実行します。FP8 保存は FP8 計算を意味しません。
有効な形式が 1 種類だけなら再利用します。破損ファイルはエラーを報告し、黙って上書きしません。

有効なファイルがない場合、**対応する Anima で初めて有効な生成を実行した時だけ**、
`huggingface_hub.hf_hub_download` で[作者の公式リポジトリ](https://huggingface.co/0ppxnhximxr/snapref-v2a-pre2)
から取得します。解決したリビジョンの固定、進捗、3 回の試行、タイムアウト、ファイルロック、
サイズ・SHA256・全テンソルの検証、アトミックな配置に対応します。一時配置ファイルは
消去し、HF の再開可能キャッシュは残る場合があります。指定フォルダーが書込不可なら
Forge のローカルモデルフォルダーを使用し、実際の保存先を表示します。

**学習済み重みは GPL ではなく CircleStone Labs 非商用ライセンス v1.2 です。**
生成前に通知を表示します。利用前にモデルのライセンスを確認してください。重みは同梱しません。
ネットワーク障害時はその生成を中止し、WebUI は継続します。既存のプロキシを修正するか、
公式ファイルを手動配置して再スキャンできます。開発環境のプロキシ TLS 障害により実際の
ダウンロード成功は未検証ですが、成功配置・失敗・中止・破損は制御された転送でテストしました。

## 互換性

* **Anima base v1.0（28 ブロック）**：実際の BF16 重みで GPU 生成を検証。
* **Anima 2.9B preview（40 ブロック）**：追加ブロックを除く上流マッピングで生成とキャッシュを検証。
* **同じ構造の微調整・Turbo**：構造検証を通る場合に使用可能。各モデルの品質保証はありません。
* **Anima 3.8B（52 ブロック）**：検証済みの上流対応表がないため拒否。
* Anima 以外は実際のエンジン・Transformer 型で拒否。MOSS の実ロード後の拒否も検証。
* 通常のキャラクター LoRA との併用を検証。Forge の既存デルタを維持します。
* Spectrum は独立参照ガイダンスなしで検証。同時有効化は明示的に拒否。
* 標準 Anima Reference/Edit と ImageStitch の参照経路は競合として拒否し、他の設定を変更しません。
* バッチ 2、CFG 1、連続生成、中止、モデル切替を検証。コンパイルモデルや他のブロック調制
  フックなどの未検証組合せは互換性を宣言しません。

バイアスがない場合は Forge の注意バックエンドを使用し、重み付き融合では局所的に
PyTorch 融合 LSE または SDPA に切り替えます。SageAttention 等を全体で無効にしません。
サンプラー・スケジュールはホストのままです。12 ステップの DPM++ 2M/Karras は暗い結果に
なったため、この環境では Euler/Simple を推奨します。

## キャッシュ・性能・メモリ

同じ画像・モデル条件では VAE、文字、K/V を再利用します。リクエスト間の K/V は
最大 2 GiB・1 件の **CPU キャッシュ**で、サンプリング中の GPU コピーは `finally` で
解放します。1 MP 参照 1 枚の BF16 K/V は約 0.9 GB で、個別画像数に応じて負荷が増えます。
メモリ不足時はまず参照解像度を下げてください。Forge の重みオフロード機構を使いますが、
全ての低メモリ構成を検証したわけではありません。キャッシュ消去、無効化、モデルロード、
スクリプトのアンロードで関連資源を解放・無効化します。NaN/Inf と OOM は生成を中止します。

512²、12 ステップ Euler/Simple、0.25 MP 参照の実測は初回 9.98 秒、キャッシュ命中
4.62 秒、サンプリング時の最大割当 GPU メモリは 6726／6195 MiB でした。環境固有の値です。

## PNG 情報・API・テスト・アンインストール

PNG 情報の `SnapRef Config` に有効状態、実モデル、アダプターの版・識別、モード、強度、
忠実度、解像度、各画像重み、ガイダンスを保存します。画像のバイト列は保存せず、復元時は
参照画像を再選択します。`/sdapi/v1/img2img` の
`alwayson_scripts["snapref-webui"]["args"]` で UI と同じ推論を使用できます。
[API の引数順と例](docs/API.md)を参照してください。

拡張ディレクトリから WebUI の Python で実行します。

```text
python -m unittest discover -s tests -v
python tools/gpu_suite.py --reference 画像の絶対パス --output 結果の絶対パス
python tools/compatibility_probe.py --reference 画像の絶対パス --output 結果の絶対パス
```

GPU テストには隔離設定の Forge `--api --port 7862` が必要です。テスト対象インスタンスの
モデル選択を変更する場合があるため、他の利用者の作業中インスタンスには向けないでください。
詳細は[テスト報告](docs/testing.md)を参照してください。公開後の更新は独立リポジトリで
`git pull` します。削除時は WebUI を停止し、`extensions/SnapRef-webui` のみ削除します。
重みはモデルフォルダーに残り、必要なら別途削除できます。ホストや共有モデル、設定を削除しません。
